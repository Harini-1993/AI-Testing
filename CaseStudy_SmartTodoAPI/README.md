# AI Task Priority App

A complete 3-phase assignment: ML model → Flask API → Load Testing → Self-Healing Tests.

---

## Project Structure

```
Case Study/
├── dataset/
│   └── tasks.csv                    # 200 labeled tasks (High/Medium/Low)
├── model/
│   ├── train_model.py               # Train and save the ML model
│   └── model.pkl                    # (Generated after training)
├── api/
│   ├── app.py                       # Flask API with /predict and /health
│   └── requirements.txt             # Python dependencies
├── k6-tests/
│   ├── ramp_up_test.js              # Gradual load test (1→10→50 users)
│   └── spike_test.js                # Spike test (5→100 users instantly)

│   ├── performance_analysis.md      # Analysis template (fill after running tests)

│   └── spike_summary.txt            # (Generated by K6)

└── README.md                        # This file
```

## Phase 1 — Build the AI API

### Step 1: Install dependencies

```bash
cd api
pip install -r requirements.txt
```

### Step 2: Train the model

```bash
cd model
python train_model.py
```

Expected output:
```
✅ Loaded 200 tasks
✅ Model Accuracy: 97.50%
✅ Model saved to: model/model.pkl
```

### Step 3: Start the Flask API

```bash
cd api
python app.py
```

The API will be available at `http://localhost:5000`.

### Test the API manually

**Predict endpoint:**
```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"task": "Fix production bug"}'
```

Expected response:
```json
{
  "priority": "High",
  "confidence": 0.97
}
```

**Health endpoint:**
```bash
curl http://localhost:5000/health
```

Expected response:
```json
{"status": "ok"}
```

## Phase 2 — Performance Testing with K6

### Install K6

**macOS:**
```bash
brew install k6
```

**Windows:**
```bash
winget install k6
```

**Linux:**
```bash
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update && sudo apt-get install k6
```

### Run Test 1 — Ramp-Up

```bash
cd k6-tests
k6 run --out json=../reports/ramp_up_report.json ramp_up_test.js
```

### Run Test 2 — Spike

```bash
cd k6-tests
k6 run --out json=../reports/spike_report.json spike_test.js
```

### Fill in the report

Open `reports/performance_analysis.md` and fill in:
- Your measured metrics
- Your answers to the analysis questions

## Phase 3 — Self-Healing Test Script

### Install requests

```bash
pip install requests
```

### Run the self-healing tests

```bash
cd self-healing-test
python self_healing_test.py
```

### What it does

| Situation | Behavior |
|-----------|----------|
| `priority` field present | ✅ PASS normally |
| `priority` missing, `level` present | ⚠️ WARN + continue |
| `priority` missing, `urgency` present | ⚠️ WARN + continue |
| No matching field at all | ❌ FAIL properly |
| `confidence` field renamed to `score` | ⚠️ WARN + continue |

### To simulate an API field change (for testing Phase 3)

In `api/app.py`, change:
```python
return jsonify({"priority": prediction, "confidence": ...})
```
To:
```python
return jsonify({"level": prediction, "score": ...})
```

Re-run the self-healing test. It should detect the rename and continue.
